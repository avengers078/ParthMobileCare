# PARTH MOBILE CARE — FIRESTORE DATA SCHEMA & SECURITY RULES SPECIFICATION

**Date:** November 3, 2026  
**Infrastructure:** Firebase Spark Plan (Free Tier)  
**Database:** Cloud Firestore  
**Rule File:** `firestore.rules`  

---

## 1. Overview & Schema Design Principles

The Parth Mobile Care database operates on a serverless, client-synchronized Cloud Firestore architecture under the Firebase Spark Plan. In the absence of Cloud Functions, all security, document immutability, role-based access control (RBAC), and relational integrity are strictly enforced through declarative **Firestore Security Rules**.

Every collection uses explicit field allowlists (`hasOnly()`), required field assertions (`hasAll()`), type validations, length bounds, and ownership checks.

## 2. Collection Schemas & Security Rules

### 2.1. `users` Collection
- **Document Path:** `users/{userId}` (where `userId == request.auth.uid` or provisioned ID)
- **Purpose:** User profile, role, compensation, device binding, and biometric face enrollment state.

| Field Name | Type | Required? | Description / Allowed Values | Security Rule Enforcement |
|:---|:---|:---:|:---|:---|
| `id` | `string` | Yes | Unique Firebase Auth UID | Must equal document ID (`userId`) |
| `name` | `string` | Yes | Full employee name (1–100 chars) | String length checked |
| `email` | `string` | Yes | Employee email address | Valid email pattern |
| `phone` | `string` | Yes | 10-digit mobile number | Validated numeric string |
| `role` | `string` | Yes | `'admin'` or `'staff'` | Staff cannot modify; Admin only |
| `designation` | `string` | Yes | Job title (e.g. Sales Executive) | String length checked |
| `avatarUrl` | `string` | No | Optional profile photo URL | String length checked |
| `joinedDate` | `string` | Yes | ISO Date string (`YYYY-MM-DD`) | Set at registration |
| `basicSalary` | `number` | Yes | Monthly base compensation ($\ge 0$) | Admin only editable |
| `monthlyTarget` | `number` | Yes | Monthly sales quota ($\ge 0$) | Admin only editable |
| `isActive` | `boolean` | Yes | Account active status (`true`/`false`) | Admin only editable; deactivates session |
| `deviceId` | `string` | No | Unique hardware identifier | Immutable once approved |
| `devicePublicKey` | `string` | No | ECDSA public key from device keystore | Immutable once approved |
| `deviceModel` | `string` | No | Device model string | Hardware metadata |
| `devicePlatform` | `string` | No | `'android'` or `'ios'` | Platform metadata |
| `deviceBindingStatus`| `string` | No | `'unregistered'`, `'pending_approval'`, `'approved'`, `'rejected'` | Only Admin can transition to `'approved'` |
| `deviceRegisteredAt` | `string` | No | ISO Timestamp | Client / server timestamp |
| `deviceApprovedAt` | `string` | No | ISO Timestamp | Set on admin approval |
| `deviceApprovedBy` | `string` | No | Admin UID | Set on admin approval |
| `deviceRejectionReason`| `string`| No | Admin rejection reason | Set on admin rejection |
| `hasFaceRegistered` | `boolean` | No | Real-time face registration flag | Set when embedding is uploaded |
| `faceRegistrationDate`| `string` | No | ISO Date string | Biometric enrollment date |
| `faceEnrollmentStatus`| `string` | No | `'unregistered'`, `'pending_approval'`, `'approved'`, `'rejected'` | Admin only can approve/reject |
| `faceApprovedAt` | `string` | No | ISO Timestamp | Set on admin face approval |
| `faceApprovedBy` | `string` | No | Admin UID | Set on admin face approval |
| `faceRejectionReason`| `string` | No | Admin rejection reason | Set on admin face rejection |
| `faceEmbedding` | `list` | No | Float array ($\le 512$ floats) | Mobile model output embedding |

- **Security Rules:**
  - `read`: Authenticated user can read own profile; Admin can read all profiles.
  - `create`: Owner or Admin can create profile; role must be `'staff'` unless caller is already an admin.
  - `update`: Staff can only update non-privileged fields (`name`, `phone`, `avatarUrl`, initial device/face registration if unregistered). Staff cannot change their own `role`, `isActive`, `basicSalary`, `monthlyTarget`, or approve their own device/face. Admin has full update rights.
  - `delete`: Admin only.

### 2.2. `staff_invitations` Collection
- **Document Path:** `staff_invitations/{token}`
- **Purpose:** Secure invitation tokens generated by Admin to invite new staff.

| Field Name | Type | Required? | Description / Allowed Values | Security Rule Enforcement |
|:---|:---|:---:|:---|:---|
| `id` | `string` | Yes | Document identifier | Unique ID |
| `token` | `string` | Yes | 16-character alphanumeric token | Unique lookup key |
| `name` | `string` | Yes | Employee name | Immutable after creation |
| `email` | `string` | Yes | Employee email | Immutable after creation |
| `phone` | `string` | Yes | Employee phone | Immutable after creation |
| `role` | `string` | Yes | Must be `'staff'` | Immutable |
| `designation` | `string` | Yes | Job title | Immutable after creation |
| `basicSalary` | `number` | Yes | Base compensation | Immutable after creation |
| `monthlyTarget` | `number` | Yes | Monthly target | Immutable after creation |
| `createdBy` | `string` | Yes | Admin UID | Set on creation |
| `createdByName` | `string` | Yes | Admin name | Set on creation |
| `createdAt` | `string` | Yes | ISO Timestamp | Set on creation |
| `expiresAt` | `string` | Yes | ISO Timestamp (e.g. 7 days) | Checked during redemption |
| `status` | `string` | Yes | `'pending'`, `'accepted'`, `'revoked'`, `'expired'` | Single-use: transitions to `'accepted'` |
| `acceptedAt` | `string` | No | ISO Timestamp | Set on redemption |
| `acceptedByUid` | `string` | No | New Staff UID | Set on redemption |

- **Security Rules:**
  - `read`: Admin can read any token; non-admin can only read specific document by exact token key (`allow get`). Public list queries are prohibited to prevent token enumeration.
  - `create`: Admin only.
  - `update`: Authenticated users redeeming a pending, non-expired token can only modify `status`, `acceptedAt`, and `acceptedByUid` using `diff().affectedKeys().hasOnly(['status', 'acceptedAt', 'acceptedByUid'])`. All compensation, role, and identity fields are immutable.
  - `delete`: Admin only.

### 2.4. `attendance` Collection
- **Document Path:** `attendance/{attendanceId}`
- **Purpose:** GPS-geofenced and biometric-verified shift attendance records.

| Field Name | Type | Required? | Description / Allowed Values | Security Rule Enforcement |
|:---|:---|:---:|:---|:---|
| `id` | `string` | Yes | Format `att_{userId}_{YYYY-MM-DD}` | Unique daily punch ID |
| `userId` | `string` | Yes | Staff member UID | Must equal `request.auth.uid` |
| `userName` | `string` | Yes | Staff name | Populated from profile |
| `userRole` | `string` | Yes | Role | Populated from profile |
| `date` | `string` | Yes | Format `YYYY-MM-DD` | Checked against server timestamp |
| `punchInTime` | `string` | No | Format `HH:MM AM/PM` | Set at punch in |
| `punchInCoords` | `map` | No | `{latitude, longitude, distanceMeters, ...}` | Verified within allowed radius |
| `punchOutTime` | `string` | No | Format `HH:MM AM/PM` | Set at punch out |
| `punchOutCoords`| `map` | No | `{latitude, longitude, distanceMeters, ...}` | Verified within allowed radius |
| `status` | `string` | Yes | `'present'`, `'late'`, `'half_day'`, `'early_exit'`, `'absent'` | Calculated or corrected status |
| `totalHours` | `number` | Yes | Hours worked ($\ge 0$) | Computed at punch out |
| `isLate` | `boolean` | Yes | Whether shift started past grace period | Evaluated against store hours |

| `verificationMethod`| `string`| No | `'face_recognition'`, `'manual_override'` | Mode of identity verification |
| `faceVerificationScore`| `number`| No | Embedding cosine similarity score | Recorded for verification audit |
| `deviceId` | `string` | No | Hardware ID used for punch | Must match bound device |

- **Security Rules:**
  - `read`: Staff can read their own punches; Admin can read all.
  - `create`: Staff can create for own UID with valid geofence coordinates.
  - `update`: Staff can update own record (e.g. to punch out); Admin can correct records.
  - `delete`: Admin only.

## 3. Recommended Firestore Composite Indexes

To maintain instant query responses without incurring index billing surprises under Spark quotas:

1. **`attendance`**:
   - `userId` (Ascending) + `date` (Ascending) — For monthly payroll queries.
   - `date` (Descending) + `userId` (Ascending) — For daily store punch logs.
2. **`leads`**:
   - `status` (Ascending) + `createdAt` (Descending) — For funnel pipeline views.
   - `assignedTo` (Ascending) + `status` (Ascending) — For staff-specific leads.
3. **`second_hand_purchases`**:
   - `status` (Ascending) + `purchaseDate` (Descending) — For in-stock inventory listings.
4. **`second_hand_sales`**:
   - `soldByStaffId` (Ascending) + `saleDate` (Descending) — For staff commission attribution.
5. **`admin_audit_logs`**:
   - `timestamp` (Descending) — For chronological security inspection.
